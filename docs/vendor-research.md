# Vendor contracts for codex-harness-connect

Observed: 2026-10-01 03:52 UTC / 05:52 Europe/Amsterdam. Scope: official Claude Code subprocess, Claude Code with Z.AI GLM Coding Plan, official Grok Build. No installation, model request, login, credential-file read, or config change was performed. Frontier-research was applied. Done for this research: primary-source contracts, material incompatibilities, and explicit runtime/legal gaps; live integration remains unverified.

## Decision

Use distinct adapters. Claude has `stream-json`; Grok has `streaming-json` and a more expressive ACP transport. “Claude with zcode” should mean the verified `claude` executable with a GLM provider profile, unless local inspection proves what the user's `zcode` command does. Current ZCode is a separate desktop harness, and its public docs do not establish a standalone headless `zcode` CLI contract. [Claude CLI](https://code.claude.com/docs/en/cli-reference), [Grok scripting](https://docs.x.ai/build/cli/headless-scripting), [ZCode Agent](https://zcode.z.ai/en/docs/agents).

Grok Build is official: xAI's own docs describe the agent, executable and ACP integration; the vendor links its Rust repository, which states that official releases install the binary as `grok`. Do not substitute unrelated third-party packages named grok. [xAI overview](https://docs.x.ai/build/overview), [official source](https://github.com/xai-org/grok-build), [official open-source page](https://x.ai/open-source).

## Claude Code adapter

| Operation | Contract and evidence |
|---|---|
| Detect | Resolve the installed `claude` executable and use read-only version/help checks. Native release command is `claude`; official CLI also documents `auth status` as JSON. A documentation capability is not proof that the installed version supports it. [CLI reference](https://code.claude.com/docs/en/cli-reference) |
| One turn | Spawn with argv, explicit cwd and `-p`; stdin supports text. Check stdout result and exit status; in-run errors may appear on stdout. [Headless](https://code.claude.com/docs/en/headless) |
| Stream | `--output-format stream-json --verbose`; `--include-partial-messages` adds deltas. Await the final result; partial text is incomplete. [Headless](https://code.claude.com/docs/en/headless) |
| Resume | Persist returned `session_id`; the next process uses `--resume <id>`. Avoid `--continue` for concurrent automation because it selects the most recent conversation for a directory. `--no-session-persistence` prevents resume. [CLI reference](https://code.claude.com/docs/en/cli-reference) |
| Cancel | SIGINT ends the turn; SDK exposes `interrupt()`. SIGTERM exits 143, kills an active Bash process tree, runs SessionEnd hooks and leaves the interrupted turn unfinished. It is not successful completion. [Headless, Stop a run](https://code.claude.com/docs/en/headless) |
| Approval | Default permissions retain vendor enforcement. For a CLI host, documented `--permission-prompt-tool` delegates non-interactive approval to MCP. SDK `canUseTool` receives tool name/input and allows or denies; `AskUserQuestion` uses the same callback. An unattended route can deny prompts (`dontAsk`, or newer `--permission-prompts none`), but that is a deliberate reduced-capability mode, not interactive approval parity. [CLI reference](https://code.claude.com/docs/en/cli-reference), [SDK user input](https://code.claude.com/docs/en/agent-sdk/user-input), [permissions](https://code.claude.com/docs/en/permissions) |
| MCP | Load an explicit per-run `--mcp-config`; `--strict-mcp-config` restricts discovery to it, subject to managed policy. `claude mcp serve` exposes Claude's tools to an MCP client; it must not be presented as an equivalent prompt/session agent protocol. [MCP docs](https://code.claude.com/docs/en/mcp) |
| Skills | Standard project/personal/plugin `SKILL.md` discovery applies. Headless normally loads customization. `--bare` skips discovery **and subscription credentials**; avoid it as the subscription adapter's default. [Skills](https://code.claude.com/docs/en/skills), [Headless, bare mode](https://code.claude.com/docs/en/headless) |
| Teams | Native agent teams are experimental, off by default, and require interactive sessions. `-p`/SDK cannot spawn teammates even when enabled; ordinary subagents remain available. Resume does not restore in-process teammates. [Agent teams, Enable/Limitations](https://code.claude.com/docs/en/agent-teams) |

Parser guidance (inference from official SDK types): recognize system, assistant, user, stream-event, result and future unknown events separately; preserve session IDs and parent tool-use attribution. Success requires an appropriate terminal result, `is_error == false` and a compatible exit status. The official result type includes subtype, turn count, session ID, usage, optional result/structured output, permission denials, errors and terminal reason. [Official Python SDK types, ResultMessage/StreamEvent](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/types.py). Cost is a client estimate; resumed totals can include previous runs, so do not add them as new charges. [Headless, costs](https://code.claude.com/docs/en/headless).

Do not hand-build undocumented bidirectional CLI control messages merely because the SDK uses them. A CLI-only implementation can initially support one-turn JSON plus persisted resume, then use a documented MCP approval host or the SDK when an API-key-backed application actually needs interactive controls. This is an implementation recommendation, not a vendor mandate.

## Claude Code + GLM / zcode profile

Z.AI officially documents Claude Code with its Anthropic-compatible endpoint. The minimum provider mapping is `ANTHROPIC_BASE_URL=https://api.z.ai/api/anthropic` and `ANTHROPIC_AUTH_TOKEN=<user-provided Z.AI key>`. The page also lists alias model mappings and an extended timeout. Its current general default list and manual example differ between Flash and flagship models; choose an explicitly requested/available GLM model rather than silently adopting one of those conflicting defaults. [Z.AI Claude integration, Step 2](https://docs.z.ai/devpack/tool/claude).

The official helper/installer modifies `~/.claude/settings.json`. Do **not** execute it for this integration. Instead supply provider values only to the child process and select a separate `CLAUDE_CONFIG_DIR` for the GLM profile if isolation is needed. Anthropic documents that this separates settings, history, plugins and claude.ai credentials, including the macOS Keychain entry. Ordinary `claude` retains its normal directory/login. This uses a documented feature, while the exact GLM profile is an integration design that still needs live validation. [Z.AI integration](https://docs.z.ai/devpack/tool/claude), [Claude multiple accounts and credential management](https://code.claude.com/docs/en/authentication), [configuration directory](https://code.claude.com/docs/en/env-vars).

Auth precedence matters: selected cloud-provider credentials precede the bearer-token environment value; bearer token precedes API key/helper/OAuth. A GLM process must fail with a clear profile conflict when the user's selected cloud route or managed policy prevents that routing. Do not erase credentials, overwrite ordinary shell exports, or weaken managed provider rules. Settings `env` can overwrite shell variables, so child environment alone is insufficient isolation from a conflicting profile. Per-session `--settings` is documented and has precedence over ordinary settings, below managed settings. [Authentication, precedence/provider restrictions](https://code.claude.com/docs/en/authentication), [settings precedence](https://code.claude.com/docs/en/settings), [environment variables](https://code.claude.com/docs/en/env-vars).

The process protocol, resume, cancellation and approval behavior come from the installed Claude Code binary. GLM supplies inference; Claude features requiring Anthropic service access need separate capability checks. A custom base URL disables Remote Control and normally disables MCP deferred tool search. Do not enable tool-search compatibility without confirmation that the endpoint accepts the required blocks. [Environment variables, ANTHROPIC_BASE_URL](https://code.claude.com/docs/en/env-vars).

Current ZCode's own agent uses `AGENTS.md`, its own permission modes and model configuration; old Claude instructions are only a migration source. ZCode's desktop OpenAI Coding Plan endpoint (`/api/coding/paas/v4`) is distinct from the Claude Anthropic route above. Keep those routes named separately. No public headless zcode adapter was confirmed within current official Agent, Install, model-connection and legacy framework pages; this is a scoped gap, not proof no CLI exists. [ZCode Agent](https://zcode.z.ai/en/docs/agents), [model connections](https://zcode.z.ai/en/docs/configuration), [installation](https://zcode.z.ai/en/docs/install), [legacy frameworks](https://zcode.z.ai/en/newdocs/agent-framework).

## Grok Build adapter

| Operation | Contract and evidence |
|---|---|
| Detect | Official release executable is `grok`. Vendor documents `grok version`, `grok --help` and inspect JSON. Npm distributor is `@xai-official/grok`; shell installer is vendor-owned. Research did not install either. [CLI reference](https://docs.x.ai/build/cli/reference), [official source](https://github.com/xai-org/grok-build), [enterprise distribution](https://docs.x.ai/build/enterprise) |
| One turn | `-p` / `--single`; output plain, JSON, or **streaming-json** NDJSON. Add per-invocation `--no-auto-update` for automation rather than editing global settings. [Scripting](https://docs.x.ai/build/cli/headless-scripting) |
| Resume | Record `sessionId` from JSON; use `-r <id>`. Current docs conflict on whether `-s` creates or resumes; the Sessions page says it creates a new UUID. Do not use `-s` to resume. [Sessions](https://docs.x.ai/build/features/sessions), [Scripting](https://docs.x.ai/build/cli/headless-scripting) |
| Permissions | Ask is default; allow/deny rules are vendor-enforced and deny wins. `dontAsk` denies actions without explicit allowances. `--always-approve` removes routine approvals and is not a required adapter option. [Permissions](https://docs.x.ai/build/features/permissions), [enterprise headless modes](https://docs.x.ai/build/enterprise) |
| MCP | Vendor supports stdio and remote HTTP, OAuth, and namespaced tools; list/doctor have JSON. No automatic MCP registration or login is required by the connector. [MCP servers](https://docs.x.ai/build/features/mcp-servers) |
| Skills/subagents | Skills load from project/user `.grok/skills`, plugins and configured extra paths. Subagents are child sessions returning a summary. Docs establish subagents; no Claude-style shared native-team contract was confirmed. Grok skill `allowed-tools` frontmatter does not itself grant or restrict tools. [Skills](https://docs.x.ai/build/features/skills-plugins-marketplaces), [Subagents](https://docs.x.ai/build/features/subagents) |
| Auth/billing | Official CLI owns browser/device login. API-key automation is documented. Effective credential precedence is per-model config key > model env-key > active session > `XAI_API_KEY`; an inherited key does not necessarily change billing away from a logged-in session. Preserve user's chosen auth method and do not inspect auth files. [Enterprise authentication](https://docs.x.ai/build/enterprise) |

For bidirectional approvals/cancellation, prefer `grok agent stdio`, vendor-documented JSON-RPC ACP v1. Sequence: initialize and inspect returned capabilities/auth methods; authenticate through a returned method; create/load the session; prompt. Assistant text arrives through `session/update`, while the prompt response reports stop metadata. Keep stderr diagnostic and stdout protocol channels separate. The official source implements load, resume, close and cancel methods; capability negotiation still governs what an installed version supports. [Grok ACP example](https://docs.x.ai/build/cli/headless-scripting), [official ACP implementation](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/agent/mvp_agent/acp_agent.rs).

ACP host requirements: handle incoming `session/request_permission` with session/tool IDs and the offered option IDs. Denial and cancellation are distinct. On `session/cancel`, resolve pending permission requests with cancelled outcome, continue consuming in-flight updates, and wait for the original prompt's cancelled stop reason. Do not equate killing only the client with confirmed cancellation of vendor work. Grok's source has a session cancellation handler; the full permission path was not independently located in the published source during this bounded check. Therefore approval parity must be tested, not marked live-verified. [ACP tool calls](https://agentclientprotocol.com/protocol/v1/tool-calls), [ACP cancellation](https://agentclientprotocol.com/protocol/v1/prompt-turn), [Grok source, cancel](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/agent/mvp_agent/acp_agent.rs#L1878).

Grok headless JSON event details are not fully specified by the public scripting page. A durable parser must obtain a versioned vendor fixture before assuming Claude-like fields. TUI Esc/Ctrl+C cancellation is documented; exact headless signal exit/result semantics remain a runtime gap. ACP gives a better specified cancellation contract. [Keyboard shortcuts](https://docs.x.ai/build/keyboard-shortcuts), [Scripting](https://docs.x.ai/build/cli/headless-scripting).

## Legal and access gates

- **Claude personal CLI:** Current vendor rules allow an end user to log into the unmodified Claude Code binary with their own subscription, including on a host platform. Product embedding follows Commercial Terms and must keep the binary/auth methods intact; the platform must not pay for, resell or intermediate the end user's usage. Do not extract, store or proxy Claude.ai credentials. [Legal/compliance, product embedding and authentication](https://code.claude.com/docs/en/legal-and-compliance).
- **Claude SDK/product:** Separate vendor SDK guidance prohibits third-party developers offering Claude.ai login/rate limits without prior approval; use API-key authentication for such a product. This is not an absolute prohibition on the personal CLI subprocess above. [SDK overview](https://code.claude.com/docs/en/agent-sdk/overview).
- **GLM Coding Plan:** Quota is limited to officially supported tools and the individual account holder. The terms exclude general model-API calls from own apps/bots/sites/SaaS without a written agreement and prohibit repackaging, aggregating/proxying or supplying model capability to third parties. Claude Code is explicitly documented as a supported tool. The classification of an arbitrary new wrapper is not independently approved by that listing; keep this as personal use of the supported binary and obtain vendor confirmation before claiming a general service entitlement. [Subscription terms §4](https://docs.z.ai/legal-agreement/subscription-terms), [official Claude integration](https://docs.z.ai/devpack/tool/claude).
- **Grok:** xAI explicitly documents headless scripts/bots and ACP app integration, so the transport is sanctioned technical surface. Consumer terms prohibit account credential sharing; source-code Apache licensing does not establish resale/subscription rights. Do not promise that every subscription grants the same models/quota or that public redistribution of subscription-backed service is permitted. A vendor Warp integration announcement proves that specific integration, not blanket approval. [Overview](https://docs.x.ai/build/overview), [consumer terms §2/§3](https://x.ai/legal/terms-of-service), [source license](https://github.com/xai-org/grok-build), [Warp announcement](https://x.ai/news/grok-warp).
- **Access/runtime:** Installed executable provenance/version, locally authenticated status, model entitlement, exact GLM behavior, Grok stream schema, approvals, resume and cancellation were not exercised. No provider should be labelled connected solely from a command being on PATH. Use states detected / configured / blocked / verified, with the last requiring an explicitly authorized real roundtrip and authoritative result/session readback.

## Minimal live acceptance plan for the implementer

This is proposed future validation, not performed research: one read-only temporary workspace task per approved provider; parse stream/final result; persist ID; resume with a second read-only prompt; trigger a harmless unapproved operation and verify deny/approve handling; cancel a long operation and verify its terminal state plus absence of active child command. Confirm the original Claude login/config fingerprint is unaffected by the GLM profile. Use user's explicitly selected billing route; do not silently fall back to paid API or another provider. Native teams remain unsupported in the headless Claude adapter even if all these tests pass.
