# Architecture

1. Codex parent session uses the packaged research/delegation skills and MCP tools.
2. The registry selects a distinct reviewed native adapter; policy holds fail closed.
3. Inventory verifies installed executable identity and top-level help/version; help is untrusted evidence.
4. A launch contract builds an argv vector without a shell and keeps vendor auth/default policies intact.
5. A detached local worker owns one native process, PTY or pipe, controls and durable event cursors.
6. Codex consumes bounded event pages and explicit native answers/cancellation. Reconnection never starts
   another inference run. External tasks are not misrepresented as native Codex subagent sessions.
7. Explicit native git worktrees isolate concurrent changes; they do not claim managed Codex attachment.

The OS job id, native conversation id, worker PID/process identity, child process group and workspace
are separate identities. Native terminal success, process exit and actual task acceptance are separate
facts. Environment secrets must not enter payload files, transcripts or public generated packages.

## Required next layers

Versioned stream parsers and native terminal results; recursive CLI dossiers; documented Claude approval
host and Grok ACP permission broker; teams capability negotiation; MCP UI progress/terminal rendering;
registry extension workflow with source/test gates; retention/cleanup; explicit per-session context
provenance; migration and update gates; real Desktop acceptance.
